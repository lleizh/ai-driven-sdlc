## Background（背景）

現在の SDLC コマンド（11個）に対する品質レビューの結果、67個の問題が発見されました：
- 19個の重大な問題（Critical）
- 18個の高優先度問題（High）
- 17個の中優先度問題（Medium）
- 13個の低優先度問題（Low）

主な問題：
1. **コード重複**: Metadata 更新パターンが 6+ コマンドに重複、ブランチ切り替えロジックが 3箇所に重複
2. **複雑性**: `/sdlc-init` が 44ステップ、`/sdlc-decision` の Blocker チェックが 20+ サブステップ
3. **標準不一致**: Commit メッセージ形式、エラーメッセージ、セクション構成が統一されていない
4. **プラットフォーム互換性**: macOS 専用の `sed -i ''` が Linux で動作しない
5. **エラー処理不足**: Feature 存在チェック、GitHub 認証チェックが欠落

これらの問題により、保守性が低く、変更時に複数ファイルの修正が必要になっています。

## Problem Statement（課題）

SDLCコマンドの現状：
- コードの重複により、バグ修正や機能追加時に複数箇所の修正が必要
- 複雑なロジックにより、理解と保守が困難
- 標準化されていない実装により、一貫性が欠如
- プラットフォーム依存のコードにより、Linux環境での動作が不安定
- 不十分なエラー処理により、ユーザー体験が低下

## Goals（目標）

SDLCコマンドの体系的なリファクタリングにより、以下を実現：
1. コード重複を削減（DRY原則の適用）
2. 複雑なコマンドの簡素化
3. コマンド構造の標準化
4. プラットフォーム互換性の確保（macOS/Linux対応）
5. エラー処理の強化

## Non-Goals（非目標）

- 新機能の追加（既存機能の改善に専念）
- コマンドのユーザーインターフェース変更（後方互換性を維持）
- 完全な書き直し（段階的な改善を優先）

## Constraints（制約）

- 既存のSDLCワークフローを破壊しない
- 後方互換性を維持する
- 段階的に実装可能であること（4フェーズに分割）
- 各フェーズで独立してテスト可能であること

## Success Metrics（成功指標）

- コード重複率が50%以上削減される
- `/sdlc-init`の複雑性が30ステップ以下に削減される
- 全コマンドがLinuxとmacOSの両方で動作する
- テストカバレッジが80%以上を達成する
- 全コマンドの構造が統一される（同じセクション順序）
